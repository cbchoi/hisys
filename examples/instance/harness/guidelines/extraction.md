# Extraction Harness Guideline

Traceability: HISYS-HARNESS-GUIDE-001, HISYS-FR-EXT-001..005,
HISYS-DATA-002, HISYS-T-009, HISYS-T-010.

## Purpose

Validate that extraction transforms raw evidence references into interpretation
records without copying raw payload content.

## Procedure

1. Start from one or more `RawObservation` records generated by Investigator.
2. Run the fixture-backed extractor or controlled extraction implementation.
3. Verify every `ExtractedSignal` contains:
   - at least one `observation_refs` entry;
   - `signal_type`;
   - `claim_or_event`;
   - `confidence` in `[0, 1]`;
   - `uncertainty`;
   - `contradictions` list, even when empty;
   - `extraction_method` and `version`.
4. Verify evidence/interpretation separation:
   - no raw payload is copied into `claim_or_event`;
   - raw payload remains referenced through observation IDs and payload refs.
5. Persist extracted signal JSON under:

```text
<data_root>/extracted-signals/<YYYYMMDD>/<signal_id>.json
```

## Pass Criteria

- HISYS-T-009: every signal references at least one observation.
- HISYS-T-010: confidence, uncertainty, contradiction, method, and version
  metadata are present and machine-checkable.
- No live source access is performed during extraction harness runs.
